# Job Monitor — iOS-приложение

SwiftUI-клиент (iOS 16+) поверх REST API backend'а из `../backend`. Само
приложение не сканирует сайты и не шлёт почту — это делает backend по
расписанию; приложение лишь показывает результат и позволяет управлять
источниками/критериями.

## Важно: почему здесь нет готового `.xcodeproj`

Эта сессия работала в облачном Linux-контейнере — без macOS и Xcode собрать
и подписать iOS-бинарник физически невозможно (это требование самой Apple,
а не ограничение реализации). Вместо hand-написанного `.xcodeproj` (что
ненадёжно без Xcode под рукой) здесь лежит `project.yml` — декларативное
описание проекта для [XcodeGen](https://github.com/yonaskolb/XcodeGen),
из которого `.xcodeproj` генерируется одной командой на вашем Mac.

## Установка на ваш iPhone (нужен Mac с Xcode)

1. Установите XcodeGen, если его ещё нет:
   ```
   brew install xcodegen
   ```
2. В папке `ios/` сгенерируйте Xcode-проект:
   ```
   cd ios
   xcodegen generate
   ```
   Появится `JobMonitor.xcodeproj`.
3. Откройте `JobMonitor.xcodeproj` в Xcode.
4. Выберите таргет `JobMonitor` → вкладка **Signing & Capabilities** →
   в поле **Team** выберите свой Apple ID (обычного бесплатного Apple ID
   достаточно для установки на собственный телефон; такая сборка работает
   на устройстве 7 дней, затем нужно переустановить через Xcode ещё раз —
   это ограничение Apple для бесплатных аккаунтов, не приложения. Для
   сборки без 7-дневного ограничения нужен платный Apple Developer Program).
5. Подключите iPhone к Mac по кабелю (или добавьте его по Wi-Fi через
   Xcode → Window → Devices and Simulators), разблокируйте телефон и
   при необходимости подтвердите «Доверять этому компьютеру».
6. В Xcode в выборе устройства (рядом с кнопкой Run) выберите ваш iPhone
   вместо симулятора и нажмите **Run** (▶). Xcode соберёт, подпишет и
   установит приложение на телефон.
7. При первом запуске на телефоне iOS может потребовать разрешить
   запуск приложения от неизвестного разработчика: Настройки → Основные →
   VPN и управление устройством → выбрать профиль разработчика → Доверять.

## Настройка приложения после установки

Backend должен быть уже запущен и доступен по сети с телефона (см.
`../backend/README.md`). Во вкладке **Настройки** приложения укажите:
- **Адрес backend'а** — например `http://192.168.1.10:4000`, если backend
  запущен на компьютере в той же Wi-Fi-сети, что и телефон (используйте
  локальный IP компьютера, не `localhost` — с телефона `localhost`
  указывает на сам телефон). Для доступа из любой сети backend нужно
  задеплоить на сервер с постоянным адресом (см. backend README).
- **API-токен** — то же значение, что в `API_AUTH_TOKEN` из `.env`
  backend'а.

Чтобы не вводить токен вручную при каждой переустановке, можно один раз
создать локальный (не коммитится в git) файл с значением по умолчанию:
```
cd ios/JobMonitor/Networking
cp Secrets.swift.example Secrets.swift
# впишите в Secrets.swift реальное значение defaultAPIToken
cd ../../ && xcodegen generate   # пересоздать проект, чтобы подхватить новый файл
```
Файл `Secrets.swift` в `.gitignore` — реальный токен никогда не попадёт в
публичный репозиторий. Без этого шага приложение просто попросит ввести
токен в Настройках вручную один раз — ничего не сломается.

По умолчанию приложение разрешает произвольные (в т.ч. `http://`)
соединения (`NSAllowsArbitraryLoads` в `project.yml`) — это сделано для
удобства тестирования против backend'а без TLS в локальной сети. Если
backend будет развёрнут на своём домене с HTTPS, это можно убрать.

## Вкладка «Источники» и значок «Новое»

ИИ-агент (backend, Claude + `web_search`/`web_fetch`) ищет и верифицирует
ресурсы найма по заданным параметрам (география, специализация, категории,
языки, актуальность, объём) — карьерные страницы работодателей,
Telegram-каналы, кадровые агентства, профессиональные сообщества. Поиск
запускается только вручную кнопкой (дорогая по токенам операция), во время
поиска показывается статус-бар с числом выполненных запросов и найденных
ресурсов, список обновляется по мере находок, поиск можно остановить
кнопкой без потери уже найденного. Подтверждённые ресурсы категорий
«Прямой работодатель», «Работный сайт», «Профессиональное сообщество»,
«Социальная сеть» и «Telegram-канал» автоматически становятся источниками
для ежедневного скана вакансий; кадровые/HR-агентства в скан не попадают
(у них нет обобщённо парсибельного списка вакансий на своём сайте) и
служат просто справочником с доказательствами и контактами.

Секция «Перенос на другое устройство» на этой же вкладке (кнопки
«Экспортировать каталог в файл» / «Импортировать каталог из файла»)
сохраняет весь текущий каталог источников одним JSON-файлом и позволяет
загрузить такой файл в это же приложение на другой установке — источники
добавляются/обновляются по URL, без дублей (см. `POST
/api/hiring-resources/export` и `/import` в backend README).

Вакансия помечена значком «Новое» и учтена в бейдже на вкладке «Вакансии»,
пока её не открыли (тап по названию/кнопке «Посмотреть вакансию»); ресурс
найма — пока не нажали «Просмотрено» на вкладке «Источники».

## Структура

- `JobMonitorApp.swift` — точка входа.
- `Models/` — Codable-модели, совпадающие по полям с JSON backend'а.
- `Networking/AppSettings.swift` — адрес backend'а и API-токен (токен — в Keychain).
- `Networking/APIClient.swift` — async/await клиент поверх REST API.
- `Networking/BadgeStore.swift` — общий счётчик непросмотренных вакансий для бейджа вкладки.
- `Views/` — экраны: список вакансий, названия должностей, ресурсы найма
  (список + параметры поиска), критерии, настройки.
- `ViewModels/` — состояние экранов и вызовы `APIClient`.

## Известные ограничения

Приложение собрано и установлено на физический iPhone через Xcode/`xcodebuild`
и работает. Bundle ID закреплён в `project.yml` как `com.vladislav-utkin.jobmonitor` —
это то значение, которое реально прошло автоматическую подпись (Automatic
signing, Personal Team) на используемом Apple ID; при необходимости смените
на своё.
