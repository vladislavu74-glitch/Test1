# Job Monitor — backend

Node.js + TypeScript сервис: ежедневно в 10:00 сканирует источники вакансий,
хранит состояние (скрыто/активно, выбранные источники и названия должностей)
и присылает письмо на email при появлении новых вакансий. Обслуживает REST
API для iOS-приложения из `../ios`.

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env   # заполните значения, см. ниже
npx prisma migrate deploy
npm run seed            # заполняет начальный список источников (hh.ru, SuperJob, Habr Career)
npm run dev              # запуск с автоперезагрузкой на http://localhost:4000
```

Проверка:
```bash
curl http://localhost:4000/api/health
curl -H "Authorization: Bearer <API_AUTH_TOKEN из .env>" http://localhost:4000/api/sources
```

## Переменные окружения (`.env`, см. `.env.example`)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | путь к SQLite-файлу |
| `API_AUTH_TOKEN` | токен, которым iOS-приложение авторизуется в API |
| `SUPERJOB_API_KEY` | ключ приложения SuperJob (зарегистрировать на api.superjob.ru) |
| `RESEND_API_KEY` | ключ Resend (resend.com/api-keys) для отправки email-дайджеста |
| `MAIL_FROM` / `MAIL_TO` | отправитель и получатель дайджеста (по умолчанию `vladislav.u74@gmail.com`) |
| `ANTHROPIC_API_KEY` | ключ Anthropic (console.anthropic.com/settings/keys) — нужен ИИ-агентам поиска источников вакансий и ресурсов найма (`src/discovery/*Agent.ts`) |
| `ANTHROPIC_PROXY_URL` | см. ниже — обязателен, если backend развёрнут на сервере с российским IP |
| `CRON_TZ` | таймзона ежедневного скана в 10:00 (по умолчанию `Europe/Moscow`) |
| `PORT` | порт HTTP-сервера |

### Anthropic API и российские IP

Anthropic API возвращает `403 Request not allowed` на ЛЮБОЙ запрос (не
только с `web_search`/`web_fetch`) с российских IP-адресов — это
гео-ограничение на стороне Anthropic, не проблема ключа или кода. Если
backend развёрнут на сервере с российским IP (как текущий продакшн),
задайте `ANTHROPIC_PROXY_URL="socks5://user:pass@host:port"` — адрес
SOCKS5-прокси на сервере в другой юрисдикции. `src/discovery/anthropicClient.ts`
заворачивает через него только вызовы Anthropic API, остального трафика
backend'а (hh.ru, SuperJob, Resend и т.п.) это не касается.

Письма уходят через [Resend](https://resend.com) — HTTP API поверх порта
443, а не прямой SMTP: многие VPS блокируют исходящие SMTP-порты
(25/465/587) по умолчанию как антиспам-меру, порт 443 почти никогда не
блокируется (см. `src/mail/mailer.ts`). Без верификации своего домена в
Resend можно отправлять только с адреса `onboarding@resend.dev` (значение
`MAIL_FROM` по умолчанию) и **только на email, на который зарегистрирован
сам аккаунт Resend** — отсюда `MAIL_TO=vladislav.u74@gmail.com` по
умолчанию. Верификация домена (Dashboard → Domains, несколько DNS-записей)
снимает оба ограничения: можно будет слать с адреса на своём домене на
любой получатель.

## Источники вакансий

Начальный набор (`npm run seed`, см. `src/seed.ts`): hh.ru (Россия,
Казахстан, Беларусь, Узбекистан, Киргизия — через один и тот же публичный
API hh.ru с разными `areaId`), SuperJob, Habr Career. Значения `areaId`
взяты из справочника hh.ru на момент написания — перед боевым
использованием сверьтесь с `GET https://api.hh.ru/areas` и поправьте при
необходимости в `src/seed.ts` или прямо в БД (`Source.config`).

Архитектура коннекторов расширяемая (`src/connectors/`): помимо
готовых hh.ru/SuperJob/Habr Career, есть два универсальных коннектора —
`ats_board` (для компаний, использующих Greenhouse/Lever — публичные
JSON API их карьерных страниц) и `rss_feed` (любая RSS/Atom-лента
вакансий). Новый источник такого типа добавляется без изменения кода —
достаточно вставить строку в таблицу `Source` с нужным `config`, например:

```json
{ "connector": "ats_board", "provider": "greenhouse", "boardSlug": "example" }
{ "connector": "rss_feed", "feedUrl": "https://example.com/jobs.rss" }
```

Добавлять такие источники вручную через БД не обязательно: в приложении
есть экран «Автообнаружение» (вкладка Источники), который кладёт запись в
таблицу `SourceCandidate` через `POST /api/source-candidates`.

## Автообнаружение новых источников

Единого легального способа "найти все сайты рекрутинговых компаний в
интернете" не существует, поэтому реализован практичный вариант: каталог
кандидатов (`SourceCandidate`), который пользователь пополняет сам (через
приложение или напрямую `POST /api/source-candidates`), и ежедневная
проверка (`src/jobs/discoverSources.ts`).

Для кандидатов типа `ats`/`rss` (добавлены вручную по boardSlug/feedUrl)
проверка простая — лёгкий запрос (`JobSourceConnector.probe`) убеждается,
что ресурс жив и отдаёт корректный ответ, и при успехе сразу создаёт
`Source` (`enabled: true`).

Для кандидатов типа `recruiting_agency` (добавлены по одному адресу сайта)
проверка — эвристический классификатор (`src/discovery/agencyClassifier.ts`),
реализующий критерии из требования пользователя: скачивает главную страницу
и типовые разделы (`/rabotodatelyam`, `/uslugi`, `/stoimost`, `/keysy`,
`/o-kompanii` и т.п.) и ищет там взвешенные признаки —

| Критерий | Вес |
|---|---|
| Прямое позиционирование («кадровое агентство», …) | Высокая |
| Услуги для работодателей («подбор для вашей компании», …) | Высокая |
| Форма заявки на подбор | Высокая |
| Условия (стоимость, гарантия замены) | Высокая |
| Описание процесса подбора | Средняя |
| Подтверждение опыта (кейсы, отзывы) | Средняя |
| Специализация (IT-подбор, executive search, …) | Средняя |
| Вакансии разных клиентов | Дополнительная |

и определяет один из трёх типов ресурса:

- **`recruiting_agency`** — сайт предлагает подбор для сторонних
  работодателей; `verificationStatus` = `verified` (есть подтверждение —
  форма заявки, условия или кейсы), `needs_review` (позиционирует себя как
  агентство, но без подтверждения — по практическому правилу пользователя
  такое отмечается для ручной проверки, а не отклоняется) или `rejected`
  (сигналов нет). Автоматически создаётся `Source` только для `verified`,
  и с `enabled: false` — у произвольного сайта агентства нет универсального
  API вакансий, поэтому он появляется в списке источников как
  подтверждённый ресурс, но не участвует в скане, пока для него не
  настроят конкретный коннектор.
- **`job_board`** — доска объявлений/база вакансий множества работодателей
  (не подбор под заказ) — каталогизируется, но не промоутится.
- **`employer_repository`** — на странице найдена ссылка на публичную
  доску Greenhouse/Lever (`boards.greenhouse.io/<slug>` или
  `jobs.lever.co/<slug>`) — это единственный случай с реальным рабочим
  коннектором: он тут же проверяется как обычная `ats_board`-заявка и при
  успехе сразу создаётся включённый (`enabled: true`) `Source`, который
  участвует в скане того же дня.

По каждому кандидату сохраняются `geography`, `specialization`,
`evidenceQuote` (цитата-подтверждение) и `employerContact` — чтобы можно
было обосновать включение ресурса в список, как просил пользователь.

Настоящего веб-поиска (по запросам вида `"кадровое агентство" Казань`) тут
нет — нужен внешний Search API (Bing/Google/SerpAPI) с ключом, который не
подключён. Классификатор оценивает уже известный URL — из приложения или
`POST /api/source-candidates`.

Запускается автоматически перед обычным сканом вакансий в 10:00
(`src/scheduler.ts`) и вручную кнопкой в приложении / `POST
/api/source-candidates/discover`. История запусков — `GET
/api/scan/last-discovery`.

## Как работает ежедневное уведомление

1. Каждый день в 10:00 (`src/scheduler.ts`) и по кнопке «Искать сейчас» в
   приложении (`POST /api/scan/run`) запускается `src/jobs/scan.ts`.
2. Для каждого выбранного пользователем названия должности (`JobTitle.selected`)
   и каждого включённого источника (`Source.enabled`) вызывается коннектор.
3. Найденные вакансии сохраняются (upsert по `sourceId+externalId`); по-настоящему
   новые (не встречавшиеся раньше) помечаются.
4. **Только для запуска по расписанию**: если есть новые и не скрытые
   вакансии — на `MAIL_TO` уходит одно письмо со списком (реальные ссылки,
   сортировка от свежих к старым), и они помечаются в `NotificationLog`,
   чтобы не продублировать письмо в будущем.
5. Кроме письма, новые вакансии видны и в приложении: `GET
   /api/vacancies` отмечает их `isNew: true`, `GET /api/vacancies/summary`
   отдаёт счётчик для бейджа на вкладке, а `POST
   /api/vacancies/mark-all-seen` (вызывается приложением после показа
   списка) снимает пометку.

## Деплой (чтобы скан в 10:00 реально срабатывал)

Ежедневный cron работает только пока процесс запущен — backend должен
быть развёрнут на постоянно работающем сервере (VPS, домашний сервер,
Docker-хост и т.п.), доступном с телефона:

```bash
docker compose up -d --build
```

`docker-compose.yml` поднимает контейнер с backend'ом, применяет миграции
при старте и сохраняет SQLite-базу в volume `job-monitor-data`. Не забудьте
`.env` рядом с `docker-compose.yml` и (один раз) `npm run seed` внутри
контейнера или через отдельный `docker compose run backend npm run seed`.
