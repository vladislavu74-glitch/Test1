# Job Monitor — backend

Node.js + TypeScript сервис: ежедневно в 10:00 сканирует источники вакансий,
хранит состояние (скрыто/активно, выбранные источники и названия должностей)
и присылает письмо на email при появлении новых вакансий. Обслуживает REST
API для iOS-приложения из `../ios`.

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env   # заполните значения, см. ниже
npx prisma migrate deploy
npm run seed            # заполняет начальный список источников (hh.ru, SuperJob, Habr Career)
npm run dev              # запуск с автоперезагрузкой на http://localhost:4000
```

Проверка:
```bash
curl http://localhost:4000/api/health
curl -H "Authorization: Bearer <API_AUTH_TOKEN из .env>" http://localhost:4000/api/sources
```

## Переменные окружения (`.env`, см. `.env.example`)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | путь к SQLite-файлу |
| `API_AUTH_TOKEN` | токен, которым iOS-приложение авторизуется в API |
| `SUPERJOB_API_KEY` | ключ приложения SuperJob (зарегистрировать на api.superjob.ru) |
| `SMTP_HOST/PORT/SECURE/USER/PASS` | доступ к почтовому серверу для отправки писем |
| `MAIL_FROM` / `MAIL_TO` | отправитель и получатель дайджеста (по умолчанию `V_utkin@castleduck.com`) |
| `CRON_TZ` | таймзона ежедневного скана в 10:00 (по умолчанию `Europe/Moscow`) |
| `PORT` | порт HTTP-сервера |

Для Gmail в `SMTP_*` нужен **пароль приложения**
(https://myaccount.google.com/apppasswords), а не обычный пароль аккаунта.

## Источники вакансий

Начальный набор (`npm run seed`, см. `src/seed.ts`): hh.ru (Россия,
Казахстан, Беларусь, Узбекистан, Киргизия — через один и тот же публичный
API hh.ru с разными `areaId`), SuperJob, Habr Career. Значения `areaId`
взяты из справочника hh.ru на момент написания — перед боевым
использованием сверьтесь с `GET https://api.hh.ru/areas` и поправьте при
необходимости в `src/seed.ts` или прямо в БД (`Source.config`).

Архитектура коннекторов расширяемая (`src/connectors/`): помимо
готовых hh.ru/SuperJob/Habr Career, есть два универсальных коннектора —
`ats_board` (для компаний, использующих Greenhouse/Lever — публичные
JSON API их карьерных страниц) и `rss_feed` (любая RSS/Atom-лента
вакансий). Новый источник такого типа добавляется без изменения кода —
достаточно вставить строку в таблицу `Source` с нужным `config`, например:

```json
{ "connector": "ats_board", "provider": "greenhouse", "boardSlug": "example" }
{ "connector": "rss_feed", "feedUrl": "https://example.com/jobs.rss" }
```

(В будущем стоит добавить в iOS-приложение экран для добавления таких
источников через API `POST /api/sources` — сейчас источники создаются
через seed/БД напрямую; сам API для их редактирования включения/выключения
уже есть.)

## Как работает ежедневное уведомление

1. Каждый день в 10:00 (`src/scheduler.ts`) и по кнопке «Искать сейчас» в
   приложении (`POST /api/scan/run`) запускается `src/jobs/scan.ts`.
2. Для каждого выбранного пользователем названия должности (`JobTitle.selected`)
   и каждого включённого источника (`Source.enabled`) вызывается коннектор.
3. Найденные вакансии сохраняются (upsert по `sourceId+externalId`); по-настоящему
   новые (не встречавшиеся раньше) помечаются.
4. **Только для запуска по расписанию**: если есть новые и не скрытые
   вакансии — на `MAIL_TO` уходит одно письмо со списком (реальные ссылки,
   сортировка от свежих к старым), и они помечаются в `NotificationLog`,
   чтобы не продублировать письмо в будущем.

## Тесты

```bash
npm test
```
17 тестов: юнит-тесты коннекторов (hh.ru, ATS-доски) на моках HTTP,
интеграционные тесты пайплайна скана (новые/повторные вакансии, email
только по расписанию, скрытые вакансии не попадают в письмо) и API
(авторизация, CRUD названий должностей, включение/выключение источников,
сортировка и скрытие/показ вакансий) — на отдельной SQLite-базе.

## Деплой (чтобы скан в 10:00 реально срабатывал)

Ежедневный cron работает только пока процесс запущен — backend должен
быть развёрнут на постоянно работающем сервере (VPS, домашний сервер,
Docker-хост и т.п.), доступном с телефона:

```bash
docker compose up -d --build
```

`docker-compose.yml` поднимает контейнер с backend'ом, применяет миграции
при старте и сохраняет SQLite-базу в volume `job-monitor-data`. Не забудьте
`.env` рядом с `docker-compose.yml` и (один раз) `npm run seed` внутри
контейнера или через отдельный `docker compose run backend npm run seed`.
